# Подборка MOSS-Image и видеосуперразрешения (VSR)

**Срез:** 11 ноября 2026. **Статус:** исследовательский обзор источников. Ничего не скачано, не установлено, модели не запускались. Все 33 ссылки/записи — в [машинном реестре](../studio-addons/research-moss-vsr-2026.json), включая степень проверки и ограничения.

**Идея раздела:** научиться выбирать способ под творческую задачу, а не устанавливать десятки конкурирующих LoRA, sampler-узлов и апскейлеров. Обязательного «лучшего» нет: качество зависит от исходного материала, видеокарты, модели и параметров.

## 1. Видеосуперразрешение: что с чем сравнивать

| Технология / модель | Что делает | Отличие | Где изучить |
| --- | --- | --- | --- |
| **RelayVSR** | Улучшает весь ролик на основе опорных ключевых кадров | Большой генератор для sparse references + лёгкий VSR network для всех кадров; исследовательская система | [Репозиторий](https://github.com/kopperx/RelayVSR), [статья](https://arxiv.org/abs/2609.37850) |
| **SeedVR2** | Одношаговое диффузионное восстановление видео | Акцент на деталях/реставрации | [Репозиторий](https://github.com/IceClear/SeedVR2) |
| **FlashVSR+** | Быстрый 4K VSR, hybrid attention + дистилляция | В публикации заявлен untiled 4K на RTX 4090 24 GB | [Репозиторий](https://github.com/OpenImagingLab/FlashVSR_Plus), [статья](https://arxiv.org/abs/2610.17552) |
| **SparkVSR** | Улучшение видео под контролем вручную выбранных/улучшенных кадров | Пользователь может влиять на восстановление через keyframes | [Репозиторий](https://github.com/taco-group/SparkVSR), [сайт](https://sparkvsr.github.io/) |
| **LTX-2.5** | Генерирует AI-видео (text/image/audio→video) | **Не специализированный видеосуперразрешатель**; сопоставлять с VSR только при конкретном подтверждённом enhancement-процессе | [Официальная документация](https://docs.ltx.io/models/ltx-2-5/) |
| **NVIDIA RTX Video Super Resolution** | Улучшает воспроизведение сжатого видео на поддерживаемой RTX | Часто работает внутри браузера/плеера; не тождественно экспортируемому VSR-бэкенду | [Официальное FAQ NVIDIA](https://nvidia.custhelp.com/app/answers/detail/a_id/5448) |

**Не путать:** просто «RTX» — семейство аппаратных/программных технологий, а не седьмой конкретный апскейлер. «GAN» — **класс алгоритмов**, не самостоятельная программа. Если имеется в виду конкретный GAN-upscaler, нужна ссылка/название модели. Уже известные Upscayl, Real-ESRGAN и Video2X находятся в [общем справочнике](tools-ru.md); они не дублируются новой записью.

**Два видео сравнения (SECourses):**
- [27kdYJlOONA — демонстрация 4K на разных исходных видео](https://www.youtube.com/watch?v=27kdYJlOONA) (02.11.2026).
- [QHa7-HG5cgE — сравнение движков на одном ролике](https://www.youtube.com/watch?v=QHa7-HG5cgE) (06.11.2026).

Автор сообщает о сильной разнице в скорости (например, RelayVSR против SeedVR2 на RTX 5090). **Это не универсальный рейтинг**: аппаратное обеспечение, длительность клипа, включённая загрузка модели, формат и качество результата могут менять вывод. В источниках сравнения также упоминаются собственные установщики/пресеты, часть доступа может быть платной.

**Для проверки своими силами:** взять один и тот же легально доступный материал в трёх вариантах (реальная камера, анимация, AI-генерация), ресайзить до одинакового входного разрешения и сравнить одинаковую выходную размерность/FPS. Оценивать **не только резкость**, но и мерцание, изменение лица/текста между кадрами, искусственные детали, время, VRAM, стоимость. Сохранять исходник, настройки, устройство и кадры до/после. При наличии оригинального HR считать дополнительные объективные метрики; без него субъективные сравнения не выдавать за доказанные.

## 2. MOSS — что за модель и как устроена экосистема

[**MOSS-Image (официальный проект)**](https://github.com/OpenMOSS/MOSS-Image) — семейство **Base / SFT** моделей генерации изображений, с поддержкой длинных промптов, рендеринга текста и **нативного JSON Layout** для композиции. В ComfyUI есть поддержка стандартными загрузчиками: отдельный MOSS-плагин для обычного inference необязателен. Весовые файлы DiT, text encoder и VAE устанавливаются отдельно; смотреть [официальный user guide](https://github.com/OpenMOSS/MOSS-Image/blob/main/USERGUIDE.md).

### Референсы, композиция и комиксы

| Инструмент | Практическая задача | Как использовать |
| --- | --- | --- |
| [MOSS Image Character Catalog](https://github.com/ukr8b3g-cmyk/MOSS-Image-Character-Catalog) | Найти визуальный стиль, персонажный пример и полный промпт | [Hugging Face онлайн](https://huggingface.co/spaces/hide1/MOSS-Image-Character-Catalog), без GPU/установки |
| [SwarmUI Layout Editor](https://github.com/jambavant/SwarmUI-LayoutEditor) | Расставить на холсте зоны персонажей/объектов/надписей и получить MOSS layout JSON | Открыть `standalone/index.html` в браузере, либо поставить расширение в `SwarmUI/src/Extensions/` |
| [ComfyUI MossPanelDataset](https://github.com/sepiablue-ai/ComfyUI-MossPanelDataset) | Генерировать страницу манги: 2–6 панелей, персонажи/сцены/диалоги | Установить `custom_nodes` по README; нужен MOSS |
| [52 film & camera prompts](https://robertcreative.com/blog/moss-image-film-camera-prompts) | Разобраться, как описывать фактуру плёнки, цвет и свет **без LoRA** | Прочитать статью и адаптировать промпты, устанавливать нечего |

**Поправка к краткому сообщению:** каталог содержит **314 стилей**, но не только их. По README от 10.11.2026 в полном каталоге **34 395 персонажных примеров + 314 стилей = 34 709 изображений**. Это поисковая библиотека примеров, а не средство сохранения идентичности персонажа. Автор не гарантирует точность сходства всех записей.

### Сэмплинг, ускорение и эксперименты с моделью

| Проект | Задача | Важная оговорка |
| --- | --- | --- |
| [MOSS Smart Sampler](https://github.com/VictorDmAlves/comfyui-moss-smart-sampler) | Управлять sigma schedule и preset Fast/Balanced/Realism/Quality/Turbo | **README содержит ошибочную команду clone** с `comfyui-ollama-bridge` — использовать именно URL этого репозитория. Пять пресетов, не четыре |
| [MossPhoton](https://github.com/Kostik2702/ComfyUI-MossPhoton) | Повторяемые эксперименты с sаmpler, фазами LoRA и turbo | Автор подтверждает главным образом reference для одной системы; улучшение качества не доказано |
| [HaDeS MOSS Suite](https://github.com/Devildonia/HaDeS-MOSS-Suite) | Ноды Loader, Multi-LoRA, model merger, layout, контроль и telemetry | Частично перекрывает Smart Sampler и MossPhoton; без задачи не ставить все три |
| [MOSS IDM 2 Steps](https://huggingface.co/akhaliq/MOSS-Image-IDM-2-Steps) | Черновая text-to-image генерация за 2 шага | Для T2I автор рекомендует **v1 export-750**; v2 больше для правок и ухудшает обычный T2I. Нужен **rapid-moss**, обычный LoRA Loader некорректен |
| [MossInt4](https://huggingface.co/DeltaEngine/MossInt4) | Сжатые веса MOSS для браузерного WebGPU | Существование подтверждено через HF индекс, но model card напрямую не прочитана; размер, поддерживаемый браузер и качество требуют проверки |

**Ключевое правило:** не выбирать одновременно все sampler suites. Для эксперимента сравнивать *native ComfyUI* против *одной* альтернативы при одинаковом seed/prompt/input/model; измерять не только время, но и артефакты, идентичность, точность текста.

### Обучение и рецепты

**[Fizgig](https://github.com/shootthesound/Fizgig)** — полноценная студия обучения LoRA/LoKR, slider-LoRA и экспериментального full fine-tune для MOSS-Image и ряда других генераторов. [Отдельная документация MOSS](https://github.com/shootthesound/Fizgig/blob/master/docs/MOSS_IMAGE.md). Для LoRA автор рекомендует тренировать на **MOSS Base**, а результаты просматривать на **MOSS SFT**; описаны режимы для **12 ГБ VRAM**. Это **не готовый стиль и не апскейлер**, а инструмент, чтобы научиться создавать собственные стили и персонажей. Устанавливать отдельно, без изменения базового Python окружения Clip Factory.

## 3. Возможные учебные сценарии Clip Factory

| Сценарий | Последовательность | Что понять |
| --- | --- | --- |
| **Кинопостер** | MOSS Style Catalog → SwarmUI Layout Editor → MOSS Base/SFT → выбранный film prompt → PNG | Как точное расположение текста/объектов влияет на композицию |
| **Манга с диалогом** | MossPanelDataset → MOSS → финальный макет | Насколько модель удерживает персонажей, текст и кадрирование между панелями |
| **Убрать «нейроглянец»** | MOSS SFT → отдельный un-GPT re-sample → сравнение | Что меняется в фактуре, сохраняется ли композиция |
| **Доступный inference** | Native ComfyUI → один sampler Suite → IDM (отдельно) | Качество/скорость/VRAM и воспроизводимость, не смешивать методы |
| **Улучшить фрагмент видео** | Одно видео → SeedVR2/RelayVSR/FlashVSR+ (по одному) → FFmpeg QA | На каком исходнике лучше реальная детализация без temporal flicker |

Код интеграции между этими проектами пока **не реализован**; цепочки описывают учебные задачи и возможные файловые handoff (PNG, MP4, JSON).

## 4. Как хранить новые находки

Стадии: **прислано → источник прочитан → задача понятна → установка проверена → тест выполнен → рекомендован/отклонён**. Не выдавать раннюю стадию за позднюю.

У карточки обязательно должны быть: источник, категория, задача, вход/выход, установка или способ просмотра, зависимости, ограничения, пересечения и **степень подтверждения**. «Не добавлять» означает не делать инструмент базовой зависимостью, а не терять учебную ссылку: сохранённые источники с сомнительным статусом остаются отдельно с явной маркировкой.

**Для агента:** весь каталог — в [research-moss-vsr-2026.json](../studio-addons/research-moss-vsr-2026.json); машина читает записи через `python3 scripts/studio_tools.py --json`. Перед установкой открывай официальный upstream и проверяй реальные требования, лицензии и ресурсы. Не добавляй модели/веса, ключи и готовые выходные файлы в Git.
