# Open Source Higgsfield — исследование инструментов по решаемым задачам

**Срез:** 11 ноября 2026. **Статус:** изучены публичные README и исходные репозитории, **ничего из этого списка не устанавливалось и не тестировалось в Clip Factory**. [Официальные результаты конкурса](https://comfy.org/open-source-higgsfield), объявлены 10.11.2026.

**Машинный каталог:** [research-open-source-higgsfield-2026.json](../studio-addons/research-open-source-higgsfield-2026.json). В нём все 16 уникальных проектов, включая назначение, вход/выход, тип интеграции и ограничения.

## Как читать этот каталог

Это **лаборатория инструментов**, а не перечень обязательных зависимостей. Твоя задача — не установить всё, а научиться различать **какую работу** выполняет программа, **почему выбран этот подход** и **как можно передать её результат следующему инструменту**.

Важное различие:
- **Движок**: ComfyUI, FFmpeg, Remotion. Выполняет модельный или монтажный граф.
- **Интерфейс/студия**: ComfyArt, Genobi, Creativefield, MAX Editor. Даёт человеку и/или агенту способ управлять действиями.
- **Пресеты/каталог**: Freefield. Организует много готовых сценариев поверх движка.
- **Специалист**: Paint a Plate, Henge, Reshoot 4D, OneShot MV и др. Решает одну сложную задачу.
- **Формат интеграции**: JSON workflow, Comfy SDK/API, MCP, CLI, экспорт кадров, аудио, MP4 или таймлайна.

Названия похожи, **не объединять** записи или инструкции установки.

### Проверенные технические ограничения, важные для выбора
- **Paint a Plate:** README рекомендует **32 ГБ VRAM и более**, модели около **60 ГБ**; рассчитан на тяжёлые VFX-шоты и EXR/цветоуправление.
- **MAX EDITOR:** автор тестировал RTX 3060 **12 ГБ VRAM**, но указывает **32 ГБ RAM** и примерно **70 ГБ** места.
- **Blocksfield:** в README описан GPU класса RTX 5090/32 ГБ и загрузка большого набора весов (~106 ГБ); его задача — игры.
- **ComfyArt:** локальная работа через ComfyUI, но при включении Comfy Cloud нужны ключ и возможно платные генерации; MCP/agent режим включается отдельно.
- **Creativefield:** браузерный вариант использует Comfy API key/credits, локальный — зависит от конкретных моделей.
- **Sonder Editor:** нужен совместимый ComfyUI и актуальный FFmpeg (README указывает 7+).
- **H3 Audio Retake:** отдельные lip repairs в текущем README — примерно до 7 секунд; проверить длительность и качество на реальном тесте.
- **Imagination Studio:** сначала проверить поддерживаемые платформы (Mac Apple Silicon / NVIDIA DGX Spark) — это не универсальный установщик для произвольной ОС.

Все значения — заявления upstream, **не измерения Clip Factory**. Проверяй обновлённый README и лицензии весов перед установкой.

## Чем похожие студии отличаются

| Проект | Главная сущность интерфейса | Зачем изучать |
| --- | --- | --- |
| **ComfyArt** | Свободный canvas + агент | Связь идей и ассетов, ручное+агентное управление |
| **Genobi** | Голос / поручение агенту | Организация человек → Hermes/Codex → skills/MCP → движки |
| **Creativefield** | Универсальная creative studio | Панель задач генерации, keyframes, фото/видео и визуальный контроль |
| **Imagination Studio** | Съёмочная группа / фильм | Сценарная разработка, shot planning, управление персонажами |
| **neuregex Freefield** | Каталог «приложений»-пресетов | Manifest-driven workflows, модульность, ресурсный бюджет |
| **Sonder Editor** | Таймлайн сцен и референсов | Длительная история, continuity, перегенерация участка |
| **MAX EDITOR** | Музыкальные шоты + мультитрек | Бит/сцены/текст + ручной монтаж и MCP |
| **OneShot MV** | Одна песня → целый клип | Вертикальный end-to-end pipeline для music video |

**Вывод:** не нужно одновременно ставить все восемь. Выбирай один интерфейс как предмет изучения, а специализированные инструменты подключай только ради конкретной задачи.

## Какие задачи можно попробовать решить

1. **15-секундный ролик из одной фотографии**: движение объекта по траектории в H3 Motion; сравнить с простым эффектом из FreeField.
2. **Исправление готового шота**: убрать предмет или изменить освещение через Paint a Plate, сравнить плавность в последовательности кадров и сохранение фона.
3. **Персонаж в чужой сцене**: исходный guide-видеоролик + изображения персонажа → Henge; проверить непрерывность внешности, совпадение движения, сохранение оригинального фона.
4. **Мини-история из трёх сцен**: написать идею, создать референсы в ComfyArt, составить таймлайн в Sonder, подготовить кадры/видео в ComfyUI, объединить FFmpeg/Remotion.
5. **Музыкальная нарезка**: одна разрешённая к использованию песня → OneShot MV (полная генерация) или MAX EDITOR (ручной контроль).
6. **Виртуальная камера/VR**: сравнить 360-панораму с Panorama Stickers и динамическую реконструкцию исходного видео в Reshoot 4D; это **разные техники**, не два названия одной.

## Возможные комбинации с Clip Factory

```text
Идея/задание
  ├─ [ComfyArt / Genobi / Imagination] ── референсы, сценарий, раскадровка
  ├─ [neuregex Freefield / Creativefield] ── генеративные workflow/presets
  ├─ [Sonder Editor / MAX EDITOR] ── таймлайн, ключевые кадры и версии сцен
  ├─ [Henge / H3 Motion / Paint a Plate] ── персонаж, движение, правки шота
  ├─ [Audio Retake / OneShot MV] ── специализированная работа со звуком
  └─ [clip.py / FFmpeg / Remotion] ── монтаж, финализация, QA
                                           ↓
                               Медиафайлы + метаданные
```

Это **концептуальная схема**, не подтверждённая совместимость API всех проектов. Большинство систем могут обмениваться готовыми MP4/PNG/WAV, но их внутренние project files и ComfyUI workflow не обязательно совместимы. Перед интеграцией проверить форматы ввода/вывода и требования к версиям узлов.

## Протокол исследования одного инструмента

Создавай карточку испытания, а не сразу новую систему:

```yaml
tool: Henge
research_goal: "Перенести движение на моего персонажа"
status: "не установлен"
input: "видео 5–10 секунд + изображения персонажа"
expected_output: "анимированный персонаж с сохранённым таймингом"
test_questions:
  - "Сохраняется ли лицо/внешность между кадрами?"
  - "Переносится ли движение без развала анатомии?"
  - "Можно ли повторить только неудачный шот?"
  - "Есть ли API/MCP или экспорт воспроизводимого workflow?"
metrics:
  - "время установки и скачанный объём"
  - "время обработки"
  - "пиковая RAM/VRAM"
  - "стоимость GPU/API"
  - "визуальные ошибки и ручные исправления"
result: "не тестировался"
decision: "оставить в каталоге до теста"
```

**Статусы:** `найден` → `изучен README` → `установка проверена` → `пилот завершён` → `рекомендован для задачи` → `интегрирован`. Переход требует реального подтверждения; хороший деморолик или конкурсная награда не заменяют собственного испытания.

## Как агент должен использовать эту информацию

1. По вопросу пользователя определить **тип задачи** (сцена, анимация персонажа, монтаж, VFX, звук, 3D, игры).
2. Показать 2–3 релевантных решения, а не весь каталог.
3. Уточнить существующие исходники и желаемый конечный результат; не рекомендовать устанавливать всё.
4. Сверить актуальные upstream инструкции, модели, лицензии, RAM/VRAM/место, требования безопасности.
5. Запускать установку только после разрешения; custom nodes запускать изолированно.
6. После пилота сохранить короткую карточку результата и обновить статус.
